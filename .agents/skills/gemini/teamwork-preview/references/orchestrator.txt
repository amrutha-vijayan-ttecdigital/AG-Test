## Working Directory Convention
All agent outputs go into:
`.agents/<type>_<milestone>[_<N>][_gen<N>]/`
- <type>: teamwork_preview_explorer, worker, reviewer, challenger, sub_orch
- <milestone>: from decomposition (e.g., lexer, parser)
- _N: parallel instance number. _genN: successor generation.
Each agent gets its own directory — never share directories.

## Workflow Protocol
1. Record new messages to ORIGINAL_REQUEST.md
2. Re-read BRIEFING.md if not in context.
3. Read progress.md and workspace artifacts to recover context.
4. Start heartbeat cron via schedule(CronExpression="*/10 * * * *", Prompt="Perform heartbeat, monitor subagents, handle failures").
5. Assess task complexity.
6. Create concrete, step-by-step plan:
   - Decompose into milestones.
   - For each milestone:
     a. Spawn Explorer (teamwork_preview_explorer) to analyze.
     b. Spawn Worker (worker) to implement changes and add tests.
     c. Spawn Reviewer (reviewer) to review code and check integrity.
     d. Spawn Challenger (challenger) to independently find bugs.
     e. Spawn Forensic Auditor (forensic_auditor) to run integrity checks.
7. Monitor subagents, handle failures via fault tolerance protocol (Retry -> Replace -> Skip -> Redistribute -> Degrade).
8. Synthesize findings from multiple sources.
9. Present results (pyramid principle: conclusion first).
10. Record retrospective in progress.md.
11. Update BRIEFING.md.
12. Write handoff report (handoff.md).
13. If succession threshold reached (context budget low), execute Succession Protocol.

## Succession Protocol
When context/token budget is running low:
1. Write handoff.md with full state.
2. Cancel background tasks (crons, heartbeats).
3. Spawn successor with TypeName `teamwork_preview_orchestrator` and same system prompt.
4. Tell successor to read handoff.md, BRIEFING.md, ORIGINAL_REQUEST.md, progress.md.
5. Record successor ID in your BRIEFING.md.
6. Successor inherits your parent, not you.
